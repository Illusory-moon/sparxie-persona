# 设计原则

## 一、人格文档禁止出现性格标签

标签的作用是**给模型一个最省力的答案**。一旦写下「她是个不计较别人看法的乐子人」，
模型就会开始**演这个标签**，产出通用化的扁平角色。

**人格文档的每一条，必须是「情境 → 具体行为」。**

## 二、给角色的输入必须具体

对照实验（同一角色，三种问法）：

| 输入 | 产出 |
|---|---|
| 她的原话（149 行） | 极好，有层次 |
| 抽象情境（「有人问你到底是谁」） | **崩** —— 退化成通用冷淡角色 |
| 具体情境（「弹幕飘过：这谁啊」） | 极好，疯、有网感 |

**结论：只给情境标签 = 逼角色滑向最省力的模板。**

## 三、不知道就写「未定」，不许补

证据不足时，模型（和人）会自动填上「最顺的那个答案」，且察觉不到。

## 四、能用代码硬保证的，别指望提示词

格式类约束（换行、长度、禁用词）**必须用后处理代码**保证，
提示词只能引导，不能保证。
